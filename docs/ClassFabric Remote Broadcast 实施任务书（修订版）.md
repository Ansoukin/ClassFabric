## 一、项目背景与目标

学校实际需求：教师通过手机（网页）向教室大屏所在的音响系统远程喊话（通知学生到办公室、集合等），并支持"选学生 + 选地点 → 自动合成语音呼叫"。

现有第三方方案（南山对讲等）需要独立客户端、第三方账号与频道管理，且与 ClassFabric 的课表、通知、插件生态完全脱节。本项目以 **CF 外挂插件 + 手机网页** 的形态提供自研替代。

**MVP 交付一条业务链路（验收底线）：**

```text
教师在白板端出示二维码
    ↓
手机扫码打开网页（无需选教室、无需注册）
    ↓
登记姓名（仅首次）
    ↓
勾选学生 + 选择目的地
    ↓
[立即呼叫]
    ↓
白板 Overlay「📢 刘老师正在呼叫」
    ↓
EdgeTTS 合成「请学生小陈到办公室找刘老师。」
    ↓
教室音响播放
```

## 四、产品规格（M1 / MVP）

### 4.1 白板端

**R1 服务开关与地址**
- 插件设置页可启停 HTTP 服务；默认端口 `5212`，可在 1024–65535 范围内修改；启动时端口被占用须给出明确错误与修改指引（读错误信息，不得静默失败）。
- 多网卡环境：设置页展示本机各 IPv4 局域网地址，供生成二维码时选择（默认自动选取第一个站点本地地址）；`127.0.0.1` 地址**不得**出现在二维码中。

**R2 接入码管理（v2.1 多码模型 + v2.2 教师绑定）**
- 接入码 = 32 位随机 hex；**可同时存在多枚**，设置页以列表管理：创建（必填备注，如「刘老师」）、查看二维码、创建时间、单独撤销；撤销即时失效，其他接入码不受影响；
- **教师绑定（v2.2）**：教师扫码完成登记后，其姓名自动绑定到该接入码；列表列展示「备注 / 二维码 / 绑定教师 / 绑定时间 / 创建时间」；同一码被重新登记时覆盖绑定（以最后登记者为准）；绑定信息仅存白板本地；
- 推荐实践一人一码（绑定即一一对应），机制上不限制单码使用人数；码不强制预绑身份——身份由手机端登记页填写后回传绑定；
- 接入码及其绑定信息持久化于插件配置；
- 所有 HTTP 路由（除 `404` 兜底）必须位于 `/<接入码>/` 前缀下；无效接入码一律返回 `404`（不暴露服务存在性）。

**R3 二维码**
- 每枚接入码对应一张二维码：URL = `http://<ip>:<port>/<接入码>/`（内嵌生成，可用 QRCoder 等轻量库；引入第三方库须选许可证宽松且维护活跃的包并在 README 声明）；
- 二维码随 IP/端口变更即时刷新；撤销后对应二维码即刻失效并从展示中移除。

**R4 学生名单管理**
- 设置页 CRUD：新增/改名/删除/批量粘贴导入（一行一名，可选 `姓名,分组` 格式）；可选分组展示。
- 持久化：本地 JSON（CF 插件数据目录），UTF-8；人数上限 500，超限提示。
- 名单变更即时反映到手机端（手机页下次拉取生效，M1 不要求推送刷新）。

**R5 预设目的地**
- 默认预设：办公室、实验室、医务室、德育处、门卫处；设置页可增删改排序；手机端在预设之外允许临时自定义输入（写入本次请求，不自动进入预设）。

**R6 白板提醒链路（v2.3 定稿：视觉先行 + 视听同步 + 选配语音提示）**
- 收到有效呼叫请求**立即**通过 CF 通知系统（`NotificationHostService`，注册 `NotificationProvider`）显示视觉提醒，内容为「头部：{Caller} 正在呼叫 + 正文：完整播报文本」（视听同步，见 4.3）；
- 随后进行 TTS 播报（序列与循环规则见 4.3）；播报期间 Overlay 持续显示，正文不随循环滚动刷新（循环由语音完成，视觉文字保持完整文本即可）；
- 收起时机：**TTS 播放完成事件**触发收起；兜底上限 90s（循环次数 × 名单较长时仍不足则按上限收起）；选配语音提示开启时叠加在主播报之前；
- **选配项**：设置页开关「播报前语音提示『{Caller} 正在呼叫』」（默认关）。开启时序列为：视觉提醒 → TTS「{Caller} 正在呼叫」→ TTS 主播报；
- 语音广播（P1）进行中：「🎙 {Caller} 正在广播」，结束即收起；
- 不得遮挡/修改 CF 其他 UI，样式遵循 CF 通知系统既有规范。

**R7 呼叫记录**
- 内存环形缓冲最近 20 条（UTC 时间、学生、目的地、呼叫人、结果）；设置页可查看；重启即清；不写磁盘。

**R8 播报与队列**
- M1：同一时刻仅允许一个播报任务；进行中收到新呼叫返回 `409`，手机端提示「有播报正在进行，请稍候」；
- TTS 合成与播放失败（含断网导致 EdgeTTS 不可用）须向手机端返回可读错误（不暴露堆栈），白板端记日志；
- 队列化播报列为 M2 增强项。

**R9 TTS 调用**
- 优先复用宿主语音服务（实现时核查其插件可见性与注入方式）；
- 若宿主服务不可达插件，则插件内嵌 EdgeTTS 调用（依赖形态与 CF 主仓 `vendors/EdgeTtsSharp` 一致，许可证合规）；
- 播报文本由模板生成（见 4.3），TTS 引擎只接收最终文本。

### 4.2 手机端（SPA）

**R10 接入与身份（v2.1 链路 + v2.2 绑定回传）**
- 扫码打开 `http://<ip>:<port>/<接入码>/`：首次显示**登记页**——姓名简称（2–20 字符）+ 「记住我」**可选勾选**（默认不勾选）；
- 登记提交时**回传服务端绑定**（`POST /api/register`）：接入码与该教师姓名绑定，白板端设置页即时可见（见 R2）；同名重复登记为幂等覆盖；
- 勾选「记住我」：姓名与随机 `deviceToken`（纯本地生成）写入 `localStorage`，下次打开免登记直达主页；未勾选：仅本次会话有效，关闭页面即忘（重新登记会再次覆盖绑定，属预期行为）；
- 登记页/主页均提供改名入口。

**R11 主页与 Quick Call 页**
- 主页布局（v2.1）：**QuickCall 功能卡片**（可用，点击进入呼叫页）+ **语音广播（对讲机）占位卡片**：禁用态，注明「该功能需要服务器与 HTTPS/WebRTC 基建，待公益服务器获批后评估」——占位不做任何交互行为；
- Quick Call 页：学生多选（分组折叠/搜索过滤，500 人规模须可流畅滑动）；已选学生以 chips 展示可单个移除；
- 目的地：预设 chips + 「自定义…」输入；
- 底部主按钮「📢 立即呼叫」：请求发出后进入等待态（防重复提交）；成功显示「已呼叫」反馈；`409`/失败显示可读原因；
- 页面自适应 iOS Safari / Android Chrome 竖屏，触控目标 ≥ 44px；中文界面（文案集中为键值，便于后续 i18n）。

**R12 PWA（M2）**
- `manifest.webmanifest` + 图标，支持添加到主屏幕；M1 可暂缓。

### 4.3 播报序列机制（v2.3 重写）

播报采用统一的**段序列循环**模型，单学生与多学生共用同一机制：

**段序列定义**

- **单学生**：段序列 = `[「请{Students}到{Destination}找{Caller}。」]`（例：`请小王到办公室找刘老师。`）；
- **多学生（≥2）**：段序列 = 引导句 + 名单段两段交替——
  - 引导句：`请以下学生到{Destination}来找{Caller}。`（**含呼叫人**，GM 拍板；例：`请以下学生到办公室来找刘老师。`）
  - 名单段：`小王、小陈、小张。`（学生以「、」连接，EdgeTTS 对顿号有自然停顿，兼作名字间隔）；

**循环规则**

- 段序列整体重复 N 次，N 为设置页配置项：**默认 2，范围 1–5**；
- 实现要求：将循环后的完整文本（段间以句号分隔）**一次性**提交 EdgeTTS 合成播放，由 TTS 分句机制产生自然停顿，禁止实现分段播放控制（成本与脆弱性双高）；
- 播报总文本长度上限 1000 字符，超限拒绝并提示减少学生数（500 人名单极端场景的护栏）。

**占位符与模板存储**

- 占位符仅限 `{Students}` `{Destination}` `{Caller}` 三个；模板（单学生句 / 引导句）存于插件配置（默认值内置），校验非法占位符；
- 名单连接符「、」为固定实现，不开放配置；
- Overlay 正文显示**一次**完整循环后的播报全文（循环次数 >1 时视觉不重复堆叠）；
- 代码中禁止出现硬编码的完整中文播报句子（默认模板常量除外）。

### 4.4 HTTP 接口契约（M1 全量）

所有路径以 `/<接入码>/` 为前缀（任一有效接入码皆可访问，见 R2）；响应 JSON（camelCase）；接入码无效=404。

| 方法 | 路径 | 说明 | 请求体 | 成功响应 |
|---|---|---|---|---|
| GET | `/<接入码>/` | 手机 SPA 入口 | – | HTML |
| POST | `/<接入码>/api/register` | 登记并绑定教师到本接入码 | `{teacherName:string}` | `200 {bound:true}` |
| GET | `/<接入码>/api/config` | 名单+预设目的地+版本 | – | `{roster:[{id,name,group?}], destinations:[{id,name}], version}` |
| POST | `/<接入码>/api/quickcall` | 提交呼叫 | `{students:[string], destination:string, caller:string}` | `202 {accepted:true, queuePosition:1}` |
| GET | `/<接入码>/api/status` | 服务状态 | – | `{state:"Idle|Broadcasting|Error", current:{...}?}` |
| GET | `/<接入码>/api/history` | 最近记录（≤20） | – | `{records:[{at,students,destination,caller,result}]}` |

错误语义：`400` 参数非法（含占位符校验失败）；`404` token 错误；`409` 播报进行中；`500` 内部错误（可读 message，无堆栈）。速率限制：同 IP 呼叫接口 ≤ 2 次/秒，超限 `429`。

## 五、里程碑与验收

### M0 工程骨架（0.5 天）
- 清空分支文件树 → 提交 solution/工程骨架 → 在真机 CF 2.2（Debug 构建产物 + 插件开发环境）中被加载：插件出现在已加载列表、设置页可打开。
- **验收：** 插件加载无异常日志；CF 主功能零影响；分支无 CF 主仓文件残留。

### M1 Quick Call 全链路（2 天）——**MVP 验收底线**
- 实现 R1–R7、R9、R10–R11 及全部接口。
- **验收（真机，逐条）：**
  1. 设置页导入 30+ 学生名单 → 手机端正确显示；
  2. 手机扫码 → 登记 → 选 1/2/3 名学生 → 各呼叫一次：单学生播报逐字正确；多学生为「引导句→名单」循环（含呼叫人），循环次数与配置一致；Overlay 正文同步显示完整播报文字；
  3. 自定义目的地生效；预设编辑生效；
  4. 播报中再次呼叫 → 手机端收到「请稍候」类提示（409）；
  5. 断网模拟 TTS 失败 → 手机端可读错误、白板端日志、服务不崩；
  6. 错误接入码访问 → 404；Overlay 两段式出现与消失时机正确（请求即显示「{Caller} 正在呼叫」→ 播报阶段 → 收起）；
  7. 创建两枚接入码 A/B：撤销 A 后经 A 的旧链接 404、B 不受影响；
  8. 手机主页同时呈现 QuickCall 可用卡片与语音广播禁用占位卡片（文案正确、占位无交互）；
  9. 登记后白板端设置页对应接入码显示绑定教师姓名与时间；重新登记覆盖绑定；撤销码后绑定随之消失；
  10. 关闭「语音提示」开关：链路为视觉提醒 → 主播报（无「正在呼叫」语音）；开启后可听到「{Caller} 正在呼叫」语音提示，随后主播报；
  11. 插件停用/卸载后端口释放、CF 主功能无异常；
  12. `dotnet build` 0 错误。
